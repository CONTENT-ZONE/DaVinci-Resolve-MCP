# Internal Contracts

Use this skill when "done" must be validated against the user's real objective.

## Rule

Create an internal contract before or during execution:

> Define what must be true when the task is finished.

## Contract Fields

- Objective
- Source of Truth
- Scope
- Out of Scope
- Expected Outputs
- Acceptance Criteria
- Verification
- Human Gates
- Risks / Unknowns

## Behavior

- Do not treat file creation or checklist completion as success by itself.
- Verify the expected outputs exist.
- Run relevant checks where available.
- Report changed files and remaining gaps.
